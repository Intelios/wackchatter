# Memory Nexus

Open **Memory** in the right rail and choose **Nexus** for this chat. Under **Nexus settings**, select a saved connection and independently choose the memory model. This model handles extraction and the optional **Recall more** search; changing the chat model never changes it. A deleted or missing connection pauses these operations.

New chats copy the app default. Existing conversations offer **Build from this conversation** or **Start from here**. New Nexus chats collect every 12 completed messages once configured. **Remember now**, pause, cancel and retry are available in the panel and explorer. Each accepted batch saves progress, including a valid response with no new knowledge. Errors stop the run. Normal transcript packing remains active: Nexus never automatically hides messages.

**Explore Nexus** opens the full-screen map without unmounting chat. Use pan, zoom, Fit, Centre selection or Reset; select a node to read and edit its facts and relationships. List view provides the same editing controls. Search includes names and aliases; list pages and map neighbourhoods are bounded. Motion can be disabled and respects the system's reduced-motion setting. Closing returns focus; jumping to a source retains the selection and camera for reopening.

Facts, events, current situations and unresolved threads are separate from person, place, object, event, group and concept nodes — groups cover organisations, factions, families and species; concepts cover lore, prophecies and rules. A generated statement carries message-version evidence and attribution. Changes append revisions. Earlier generated versions can be recalled as explicitly historical; manual corrections suppress automatic recall of their older text. Invalid evidence stays available for review but cannot enter automatic recall. Pins are priorities, not a way to exceed the token allowance. Delete is recoverable; show **Deleted** and restore a record or node. Deleting a node retains its independently stored memories.

**Recall more** starts from the composer draft or recent conversation. Edit the search, run it explicitly, and review the sourced findings. Checked findings are included only in the intended next request and consumed on dispatch; draft/source changes invalidate them. **Save to Nexus** is a separate permanent action. Inspect shows the current preview separately from the frozen request selection, including reasons and budget exclusions. Similarity is a search ranking, never factual confidence.

## Storage and offline operation

Canonical `ChatMetadata.nexus` records and per-chat mode use the existing revision-aware chat save queue. The disposable `nexus_embeddings` SQLite table has no effect on chat revisions. API reads and writes check the model fingerprint; vectors also require an exact content fingerprint. It shares the library database lifecycle, so backup and relocation need no additional database handle. Chat deletion cascades the cache; restoration and branching rebuild it locally. Legacy scene memories become labelled legacy events with their flags, text and available provenance; migration preserves transcript visibility.

The BGE-small-en-v1.5 q8 ONNX variant (34,014,426 bytes), tokenizer/configuration and MIT licence are included in `public/models/bge-small-en-v1.5`. `manifest.json` records the pinned upstream revision and SHA-256 hashes. Transformers.js 3.8.1 loads lazily in a Web Worker; model and WASM runtime requests remain local, with remote fetching disabled. Query jobs have priority over queued indexing. Text/graph retrieval remains usable while indexing or if local inference fails.

The default recall ceiling is 1,200 tokens, separate from lorebooks. Hybrid ranking combines text and semantic evidence, then adds a small supported graph neighbourhood; ubiquitous names cannot recursively activate the entire story. User selections, pins and active situations take priority. Historical revisions have explicit labels. The exact selected text and admission report are frozen for each request.

## Validation and limitations

Run `bun run benchmark:nexus` to regenerate `shared/nexus/benchmark-results.json`. It uses a fixed English story and development/held-out queries with the same 1,200-token ceiling for legacy keywords, text/graph and hybrid retrieval. On the current small fixture, hybrid retrieval reaches all eight held-out answers with substantially fewer unrelated facts and tokens than recursive keyword activation. This is a regression fixture, not evidence of broad real-world accuracy. Absent-answer queries are reported separately: a related candidate is not proof that an answer exists.

Timings in the benchmark are native CPU timings and process RSS, not browser memory or download timings. Browser verification uses the real local WASM worker and synthetic chat; paid-generation control flow is exercised against a local mock endpoint. Extraction quality still depends on the user's chosen memory model. English is the supported initial semantic-search language. Very small context limits or long custom instructions can leave no extraction space; the run stops with an explanation.

Tests cover hashes, provenance, history, hidden/changed sources, fork boundaries, manual/tombstone protection, malformed/empty/oversized extraction, model/content fingerprint mismatch, hard budgets, stale saves and cache lifecycle. A 4,000-node fixture exercises bounded retrieval and graph derivation. Model asset changes require updating the manifest and model/text-preparation fingerprint, then rebuilding. `scripts/vendor-nexus-model.ts` is a maintainer tool, never an installation-time download step.
